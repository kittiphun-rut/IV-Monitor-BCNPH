# เครื่องมือสร้างคู่มือพยาบาล

สร้างไฟล์ `docs/คู่มือพยาบาล_Smart_IV_Alert.docx` ตามรูปแบบเอกสารราชการไทย

```bash
tools/manual-build/run.sh
```

## รูปแบบที่ใช้

| รายการ | ค่าที่ตั้ง |
|---|---|
| ขนาดกระดาษ | A4 |
| ขอบกระดาษ | บน ๑.๕ นิ้ว · ซ้าย ๑.๕ นิ้ว · ขวา ๑ นิ้ว · ล่าง ๑ นิ้ว |
| แบบอักษร | TH SarabunPSK ขนาด ๑๖ พอยต์ (หัวข้อ ๑๘-๒๐ พอยต์ ตัวหนา) |
| เลขหน้า | มุมบนขวา — ส่วนนำใช้พยัญชนะไทย (ก ข ค ง) เนื้อหาใช้เลขอารบิกเริ่มที่ ๑ |
| โครงเล่ม | ปก · คำนำ · สารบัญ · สารบัญตาราง · สารบัญภาพ · บทที่ ๑-๗ · ภาคผนวก ก-จ · เอกสารอ้างอิง |

## สารบัญอัตโนมัติ

สารบัญ สารบัญตาราง และสารบัญภาพ เป็น **ฟิลด์ TOC จริงของ Word** ทั้งสามชุด

| คำสั่งในฟิลด์ | เก็บรายการจาก |
|---|---|
| `TOC \o "1-2" \h \z \u` | หัวข้อระดับ ๑ และ ๒ (ชื่อบท และหัวข้อย่อย) |
| `TOC \t "CaptionTable,3" \h \z` | ย่อหน้าที่ใช้สไตล์ `CaptionTable` (คำบรรยายเหนือตาราง) |
| `TOC \t "CaptionFigure,3" \h \z` | ย่อหน้าที่ใช้สไตล์ `CaptionFigure` (คำบรรยายใต้ภาพ) |

### วิธีอัปเดตสารบัญ

* **เปิดไฟล์** — ตั้ง `updateFields` ไว้แล้ว Word จะถามหรืออัปเดตให้เองตั้งแต่ตอนเปิด
* **สั่งเอง** — กด `Ctrl+A` แล้วกด `F9` หรือคลิกขวาที่สารบัญแล้วเลือก Update Field
* เลือก "Update entire table" เพื่อสร้างรายการใหม่ทั้งหมด

### ทำไมยังต้องคำนวณเลขหน้าเองอีก

ฟิลด์ TOC ที่สร้างเปล่า ๆ จะว่างจนกว่าผู้ใช้จะสั่งอัปเดต ถ้าใครเปิดแล้วสั่งพิมพ์เลยจะได้หน้าว่าง
สคริปต์นี้จึงฝัง **ผลลัพธ์ที่คำนวณไว้ล่วงหน้า** ไว้ในฟิลด์ด้วย (เหมือนที่ Word ทำเวลาบันทึกไฟล์เอง)

* เปิดแล้วพิมพ์ได้ทันที เพราะมีรายการและเลขหน้าครบอยู่แล้ว
* สั่งอัปเดตเมื่อไรก็ได้ Word จะสร้างใหม่จากเนื้อหาจริงในเล่ม

ขั้นตอนใน `run.sh` จึงเป็น

1. สร้าง .docx แล้วให้ `inject_toc_field.py` แปลงสัญลักษณ์เป็นฟิลด์ TOC จริง
2. แปลงเป็น PDF แล้วให้ `resolve_pages.py` อ่านว่าแต่ละหัวข้ออยู่หน้าใดจริง
3. สร้างใหม่โดยฝังเลขหน้าที่ได้ แล้วแปลงเป็นฟิลด์อีกครั้ง
4. ตรวจซ้ำว่าเลขหน้าไม่เปลี่ยนแล้ว (สคริปต์แจ้งผลให้)

### รูปแบบต้องไม่เพี้ยนหลังอัปเดต

เมื่อ Word สร้างสารบัญใหม่ มันจะจัดรูปแบบบรรทัดด้วยสไตล์ชื่อ `TOC 1` ถึง `TOC 9`
ถ้าไม่กำหนดไว้ Word จะใช้ค่าปริยายของตัวเอง (Calibri ๑๑ พอยต์) ซึ่งผิดรูปแบบราชการทันที
`build_manual.js` จึงกำหนดสไตล์เหล่านี้ไว้ให้แล้ว

| สไตล์ | ใช้กับ | รูปแบบ |
|---|---|---|
| `TOC 1` | ชื่อบทและภาคผนวก | TH SarabunPSK ๑๖ พอยต์ ตัวหนา ไม่เยื้อง |
| `TOC 2` | หัวข้อย่อย | ๑๖ พอยต์ ธรรมดา เยื้อง ๐.๓๕ นิ้ว |
| `TOC 3` | รายการตารางและภาพ | ๑๖ พอยต์ ธรรมดา ไม่เยื้อง |

ทุกสไตล์ตั้งแท็บชิดขวาพร้อมจุดไข่ปลาไว้ที่ขอบขวาของเนื้อที่พิมพ์ (๘๓๐๖ ทวิป)

### หมายเหตุเรื่องหัวบท

หัวบทเป็น **ย่อหน้าเดียว** ที่แสดงผลสองบรรทัด (ใช้ตัวขึ้นบรรทัดใหม่ภายในย่อหน้า)
เพราะสารบัญอัตโนมัติดึงข้อความจากทั้งย่อหน้า ถ้าแยกเป็นสองย่อหน้าจะได้แค่ "บทที่ ๑"
โดยไม่มีชื่อบทตามมา

## ข้อควรทราบเรื่องแบบอักษร

เครื่องที่ใช้สร้างเอกสารนี้**ไม่มี TH SarabunPSK ติดตั้งอยู่** ตัวเอกสารระบุชื่อฟอนต์ไว้ถูกต้องแล้ว
และจะแสดงผลถูกต้องบนเครื่องที่มีฟอนต์นี้ (เครื่องราชการไทยทั่วไปมีอยู่แล้ว)
แต่ PDF ตัวอย่างและเลขหน้าใน `pagemap.json` คำนวณจากการเรนเดอร์ด้วยฟอนต์แทน (Loma)
ซึ่ง **กว้างกว่า** TH SarabunPSK เล็กน้อย

ดังนั้นเมื่อเปิดด้วย Word บนเครื่องที่มี TH SarabunPSK จริง ควร

1. ตรวจว่าเลขหน้าในสารบัญตรงกับเล่ม หากคลาดเคลื่อน ให้แก้ตัวเลขในสารบัญโดยตรง
2. หรือรัน `run.sh` ใหม่บนเครื่องที่ติดตั้ง TH SarabunPSK แล้ว เลขหน้าจะถูกคำนวณใหม่ให้เอง

## เมื่อแก้เนื้อหาคู่มือ

แก้ในไฟล์ `part_*.js` แล้วรัน `run.sh` ใหม่ เลขหน้าในสารบัญจะถูกปรับให้เองโดยอัตโนมัติ

### ข้อควรระวังเวลาแก้ `build_manual.js`

ต้องเรียก `L.setPageMap()` **ก่อน** `require` ไฟล์เนื้อหาเสมอ
เพราะบรรทัดสารบัญถูกสร้างตั้งแต่ตอนโหลดโมดูล ถ้าตั้งตารางเลขหน้าทีหลัง
`toc()` จะถูกเรียกไปแล้วด้วยตารางเปล่า แล้วตกไปใช้เลขหน้าสำรองที่เขียนไว้ในโค้ด
ซึ่งทำให้กลไกสองรอบไม่ทำงานโดยไม่มีอะไรแจ้งเตือน

### การเน้นข้อความ

ในข้อความของ `p()` `plain()` และ `item()` ใช้ `**ข้อความ**` เพื่อทำตัวหนาได้
(`runsFrom()` ใน `manual_lib.js` แปลงให้) ถ้าไม่มีตัวช่วยนี้ ดอกจันจะติดไปบนหน้ากระดาษจริง
