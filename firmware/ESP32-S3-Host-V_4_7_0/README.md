# Central Host Gateway v4.7.0 — ตัดระบบจัดการ Wi-Fi ออก (โหมด Access Point อย่างเดียว)

ดัดแปลงจาก `ESP32-S3-Host-V_4_6_0.ino` โดยยังใช้ **Protocol v3 เดิมทุกไบต์**
จึงทำงานคู่กับเครื่องประจำเตียง **Station v7.4.x ได้ทันทีโดยไม่ต้องแฟลชใหม่**

## ปัญหาเดิมและสาเหตุ

อาการ: สมาร์ตโฟน/แท็บเล็ตเชื่อมต่อเข้าเครื่อง Host พร้อมกันได้ไม่เกิน 2 เครื่อง

สาเหตุที่พบในโค้ด v4.6.0
1. `WiFi.softAP(ssid, pass, channel)` ไม่ได้ระบุจำนวนผู้ใช้สูงสุด จึงได้ค่าปริยายของไลบรารี
   (4 เครื่อง) และเมื่ออยู่ในโหมด `WIFI_AP_STA` ทรัพยากรวิทยุถูกแบ่งไปให้ฝั่ง STA
   ทำให้จำนวนที่ต่อได้จริงลดลงเหลือ 2-3 เครื่อง
2. ฝั่ง STA พยายามต่อ Router และ **สแกนช่องสัญญาณซ้ำทุก 10 นาที** (`manageStaConnection`)
   ระหว่างสแกน ทั้ง Web Server และ ESP-NOW จะสะดุด ผู้ใช้ที่กำลังต่ออยู่หลุดได้
3. เมื่อ STA ต่อ Router สำเร็จ ช่องสัญญาณของทั้งชิปจะถูกดึงไปตามช่องของ Router
   ทำให้ SoftAP + ESP-NOW ย้ายช่องตาม และเครื่องประจำเตียงต้องไล่หาช่องใหม่

## สิ่งที่แก้ใน v4.7.0

| เดิม (4.6.0) | ใหม่ (4.7.0) |
|---|---|
| `WIFI_AP_STA` + ต่อ Router + NTP | `WIFI_AP` อย่างเดียว ไม่ต่อ Router ไม่ใช้อินเทอร์เน็ต |
| ผู้ใช้พร้อมกัน ~2-3 เครื่อง | `AP_MAX_CLIENTS = 8` เครื่อง (ปรับได้สูงสุด 10) |
| Wi-Fi power save ตามค่าปริยาย | `esp_wifi_set_ps(WIFI_PS_NONE)` ตอบสนองนิ่งขึ้นเมื่อมีหลายเครื่อง |
| ESP-NOW ส่งผ่าน `WIFI_IF_STA` | ส่งผ่าน `WIFI_IF_AP` (ไม่มี STA แล้ว) |
| เวลาจาก NTP (ต้องมีอินเทอร์เน็ต) | เวลาจากนาฬิกาเครื่องที่เปิดหน้าเว็บ + สำรองลง NVS ทุก 10 นาที |
| เมนู "จัดการ Wi-Fi" (สแกน/บันทึก/ล้าง) | หน้าต่าง "จุดเชื่อมต่อ" แบบอ่านอย่างเดียว |
| หน้าเว็บ poll ทุก 1 วินาทีเสมอ | หยุด poll เมื่อสลับแท็บ (`document.hidden`) ลดภาระเมื่อมีหลายเครื่อง |

ช่องสัญญาณของ SoftAP จึงถูกล็อกที่ CH1 ตลอดเวลา ไม่มีอะไรมาย้ายช่องอีก
ผลพลอยได้คือ ESP-NOW ของทุกเตียงนิ่งขึ้นและไม่ต้องไล่หาช่องใหม่

## การตั้งเวลา (แทน NTP)

* หน้าเว็บส่ง `POST /api/time/set?epoch=<unix utc>` ให้อัตโนมัติเมื่อเปิดหน้า และซ้ำทุก 10 นาที
* Host ตั้งเขตเวลาไทยถาวรในตัว (`ICT-7`) แล้วแปลง epoch เป็นเวลาท้องถิ่นเอง
* เวลาถูกสำรองลง NVS ทุก 10 นาที เมื่อไฟดับแล้วเปิดใหม่จะกู้เวลามาใช้ก่อน
  และแสดงว่า **"(เวลาโดยประมาณ)"** จนกว่าจะมีคนเปิดหน้าเว็บแล้วซิงก์ใหม่
* ค่า `isSynced` ที่ส่งให้เครื่องประจำเตียงยังทำงานเหมือนเดิม (มีเวลาใช้งาน = 1)

## การใช้งาน

1. เปิดเครื่อง Host
2. ที่มือถือ เชื่อม Wi-Fi ชื่อ `ESP32_Liquid_Monitor` รหัส `12345678`
   (แก้ได้ที่ `default_ap_ssid` / `default_ap_pass` ต้นไฟล์)
3. เปิดเบราว์เซอร์ไปที่ **http://192.168.4.1** (ผู้ใช้ `admin` / `password123`)
4. ถ้ามือถือเตือนว่า "ไม่มีอินเทอร์เน็ต" ให้เลือก *ใช้งานต่อ / ยังคงเชื่อมต่อ*
   (บาง Android จะสลับไปใช้เน็ตมือถือเองและปิดการต่อ Wi-Fi นี้)

จำนวนอุปกรณ์ที่ต่ออยู่ดูได้ที่แถบหัวหน้าเว็บ และที่แถบล่างของจอ OLED (`CH1 WiFi:3 | Bed:5/5`)

## โครงสร้างไฟล์ในโฟลเดอร์นี้

| ไฟล์ | หน้าที่ |
|---|---|
| `ESP32-S3-Host-V_4_7_0.ino` | เฟิร์มแวร์: การวัด แจ้งเตือน ESP-NOW และการแสดงผลบนจอ OLED |
| `web_dashboard.h` | หน้าเว็บ Dashboard (HTML/CSS/JavaScript) — เนื้อหาเดียวกับของรุ่นจอ TFT |

แยกหน้าเว็บออกจากไฟล์ .ino เพื่อให้แก้ไขง่ายขึ้น ทั้งสองไฟล์ต้องอยู่ในโฟลเดอร์เดียวกัน

## ข้อควรทราบ

* `AP_MAX_CLIENTS` ตั้งได้สูงสุด 10 ตามข้อจำกัดของ ESP32 SoftAP — ตั้งไว้ 8 เพื่อเผื่อหน่วยความจำ
  ให้ Web Server และ ESP-NOW ค่าที่มากเกินไปจะทำให้แรมไม่พอเมื่อทุกเครื่องเปิดหน้าเว็บพร้อมกัน
* Web Server ของ Arduino ทำงานทีละคำขอ หากเปิดพร้อมกัน 8 เครื่องและทุกเครื่องเปิดแท็บกราฟไว้
  หน้าเว็บอาจหน่วงเล็กน้อย — แนะนำให้ปิดแท็บที่ไม่ได้ดู (โค้ดหยุด poll ให้อัตโนมัติเมื่อสลับแท็บแล้ว)
* ไฟล์นี้ยังไม่ได้ทดสอบบนฮาร์ดแวร์จริง ตรวจแล้วเฉพาะการคอมไพล์ (ด้วย Arduino API จำลองบน PC)
