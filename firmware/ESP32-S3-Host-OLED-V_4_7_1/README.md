# Central Host Gateway v4.7.1-OLED — ใช้กับ Station v7.4.x / v7.5.x / v7.7.x

เฟิร์มแวร์ Host รุ่นจอ **OLED 1.3" ขาวดำ (SH1106 I2C)** ต่อยอดจาก `ESP32-S3-Host-V_4_7_0`
โดยยังทำงานเป็น **Access Point อย่างเดียว** และใช้ **Protocol v3 เดิมทุกไบต์**

## ความเข้ากันได้กับเครื่องประจำเตียง

ตรวจแล้วว่า **ใช้ร่วมกับ Station v7.5.1 และ v7.7.0 ได้ทันที ไม่ต้องแก้โปรโตคอล**

| สิ่งที่ตรวจ | ผล |
|---|---|
| `struct_message` (Station → Host) | 23 ไบต์ ลำดับฟิลด์ตรงกันทุกเวอร์ชัน |
| `struct_host_sync` (Host → Station) | 20 ไบต์ ลำดับฟิลด์ตรงกันทุกเวอร์ชัน |
| สูตรตัดสินสายพับ | สูตรเดียวกัน (2.5 เท่าของช่วงหยดตามเป้าหมาย ขั้นต่ำ 8 วินาที) |
| รหัสแจ้งเตือน 0-5 | ความหมายเดียวกัน |
| ช่องสัญญาณ ESP-NOW | Host ล็อกช่อง 1, Station ไล่หาช่องเองอยู่แล้ว |

ตรวจซ้ำได้ตลอดด้วย `tools/protocol-test/run.sh` ซึ่งดึงโครงสร้างจากไฟล์ `.ino`
ของทุกเฟิร์มแวร์ในที่เก็บมาเทียบกันทีละฟิลด์ — ใช้เป็นด่านกันพลาดก่อน merge

> **สิ่งเดียวที่ต่างกันคือฝั่งเซนเซอร์ ซึ่งไม่ผ่านโปรโตคอลเลย**
> v7.5.1 ใช้เกณฑ์จากหน้าคาลิเบรต 3 ขั้น ส่วน v7.7.0 ตั้งค่าตัวเองอัตโนมัติ
> ทั้งคู่ส่งผลลัพธ์ออกมาเป็น "จำนวนหยด + อัตราไหล" ในรูปแบบเดียวกัน Host จึงไม่ต้องรู้ว่า
> เตียงไหนใช้เวอร์ชันอะไร และผสมเวอร์ชันกันในหอผู้ป่วยเดียวกันได้

## สิ่งที่เพิ่มใน v4.7.1 — แจ้งเตือน "เซนเซอร์ยังไม่จับหยด"

### ช่องโหว่ที่พบ

Host เดิมมีเงื่อนไขว่าจะเตือน "สายพับ" ได้ก็ต่อเมื่อ **เคยมีหยดมาก่อน**

```c
if (... || s.totalDrops == 0 || s.msSinceLastDrop == 0) return false;   // v4.7.0
```

เตียงที่ออนไลน์อยู่ กำลังนับอยู่ แต่เซนเซอร์ **ไม่เคยจับหยดได้เลยสักหยดเดียว**
(วางเซนเซอร์ผิดตำแหน่ง สายหลุด เลนส์สกปรก) จึงขึ้นว่า **"ปกติ" ตลอดไป**

นี่คือความล้มเหลวแบบเงียบ ซึ่งอันตรายกว่าการแจ้งเตือนผิด เพราะพยาบาลเข้าใจว่าระบบ
กำลังเฝ้าอยู่ ทั้งที่ไม่ได้นับอะไรเลย — และเห็นชัดขึ้นเมื่อใช้กับ v7.7.0 ซึ่งมีสถานะ
`CHECK SENSOR` อยู่ที่หน้าจอเตียงแล้ว แต่ฝั่ง Host กับหน้าเว็บกลับไม่รู้เรื่องด้วย

### วิธีแก้

เพิ่มรหัสเตือน `ALERT_NO_SIGNAL` (6) แยกจากสายพับให้ชัดเจน เพราะสองอย่างนี้
**ให้พยาบาลไปดูคนละจุด**

| สถานะ | ความหมาย | ต้องไปดูอะไร |
|---|---|---|
| `OCCLUSION` | เคยไหลแล้วหยุด | สายน้ำเกลือ / เข็ม / ท่าแขนผู้ป่วย |
| `NO SIGNAL` | ไม่เคยเริ่มไหลเลย | **ตำแหน่งเซนเซอร์ที่กระเปาะ** |

เงื่อนไข: ออนไลน์ + กำลังนับ + `totalDrops == 0` ต่อเนื่องเกิน `NO_SIGNAL_MS` (90 วินาที)
โดยตัวจับเวลาเริ่มใหม่ทุกครั้งที่กด "เริ่มถุงใหม่" จึงไม่เตือนผิดตอนเปลี่ยนถุง

ถือเป็นเหตุวิกฤต จึงมีเสียงเตือนที่ Host ขึ้นบนจอ OLED หน้าเว็บ (🔍 เซนเซอร์ยังไม่จับหยด)
และบันทึกลงไฟล์ CSV

### ความเข้ากันได้ย้อนหลัง

**ไม่ส่งรหัส 6 ออกไปที่ Station** เพราะ Station รุ่นเก่าไม่รู้จัก ตอนส่ง Sync จะแปลงเป็น
`ALERT_NONE` เสมอ

```c
uint8_t alertCodeForStation(uint8_t code) {
  return (code == ALERT_NO_SIGNAL) ? ALERT_NONE : code;
}
```

Station ทุกรุ่นจึงทำงานเหมือนเดิมทุกประการ ส่วนเครื่องที่เตียงรุ่น v7.7.0
มีสถานะ `CHECK SENSOR` ของตัวเองอยู่แล้ว ทั้งสองฝั่งจึงบอกเรื่องเดียวกันโดยไม่ต้องคุยกัน

## การต่อสาย (เหมือน v4.7.0 ทุกประการ)

| อุปกรณ์ | ขา ESP32-S3 |
|---|---|
| OLED SH1106 SDA / SCL | GPIO 8 / GPIO 9 |
| Passive buzzer | ตามที่นิยามไว้ในไฟล์ |
| ปุ่ม POWER | ตามที่นิยามไว้ในไฟล์ |

ไลบรารีที่ต้องติดตั้ง: `U8g2` (olikraus)
